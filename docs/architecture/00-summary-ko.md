# 100meAiStore 아키텍처 요약

## 한 문장 설명

공급처 상품을 찾아 스마트스토어와 쿠팡에 등록하고 주문·재고·CS·정산을 관리하되, 돈이 나가거나 판매상태가 바뀌는 중요한 행위는 모바일 승인 후 실행하는 24시간 클라우드 위탁판매 운영 플랫폼이다.

## 사람이 하는 일

- 사업자와 판매채널 및 공급처 계정을 연결한다.
- 상품 승인함은 기본 09시·13시·17시에 확인한다.
- 발주 승인함은 기본 09시·12시·15시·18시에 확인한다.
- 발주 승인 뒤 공급처에서 직접 결제하고 증빙을 확인한다.
- 환불·보상·공급처 교체·판매중지·비정형 CS를 승인한다.
- 시간과 금액 기준은 사업자 마스터가 변경할 수 있다.

## 시스템이 자동으로 하는 일

- 공급처 API, CSV, Excel, XML 또는 수동 주문대행 자료를 같은 상품 형식으로 변환한다.
- 수익 기준을 통과한 후보를 모아 AI 분석이 필요한 일부만 OpenAI에 전달한다.
- 승인된 상품을 스마트스토어와 쿠팡 형식에 맞춰 동시에 등록한다.
- 웹훅 또는 일반 프로그램으로 주문과 재고를 계속 수집한다. 이 작업 자체에는 AI 토큰이 들지 않는다.
- 품절·마이너스 마진·불명확한 외부 실행은 안전하게 임시정지하고 질문 또는 승인을 요청한다.
- 실행마다 승인자, 근거, 정책 버전, 외부 결과와 검증 결과를 감사기록에 남긴다.

## AI 운영 원칙

- 관리자 에이전트는 기본 09시·13시·17시·21시에 변경분만 묶어서 처리한다.
- 사업자별 OpenAI API 키와 비용한도를 사용하며 플랫폼 관리자는 키 원문을 볼 수 없다.
- 정상 주문은 규칙 엔진이 처리하고 예외만 AI가 읽는다.
- AI는 DB, 판매채널 키 또는 결제수단에 직접 접근하지 않고 형식이 고정된 Tool Gateway만 호출한다.
- 정보가 부족하거나 여러 뜻으로 해석되면 추측하지 않고 부족정보·영향·선택지·권장안·무응답 안전조치를 질문한다.

## 장애와 비용

- Google Cloud의 scale-to-zero 실행을 우선하고 월 24,000원에 경고, 30,000원에 비필수 이미지·영상·조사를 중단한다.
- 주문·재고·승인·안전·알림은 비용한도나 AI 장애가 생겨도 계속 작동한다.
- Cloud SQL이 월 30,000원 안에 들어온다고 가정하지 않는다. 배포 직전 실제 견적과 외부 serverless PostgreSQL을 비교한다.
- 모든 거래는 멱등성 키, 이벤트 원장과 outbox를 사용해 재시작 후 중복 발주 없이 복구한다.
- 긴급정지는 전체·사업자·채널·공급처·상품 단위이며 점검 후 선택적으로 복구한다.

## 개발 시작 전 남은 외부 확인

- 첫 공급처와 실제 API/파일/주문대행 계약 조건
- 스마트스토어와 쿠팡의 실제 판매자 인증 및 API 권한
- 실제 주문량에 따른 재고 조회주기와 허용 지연
- 사업자·주문·정산 자료의 법정 보존기간
- 자동 가격변경의 최대 변동률
- PostgreSQL 실제 호스팅 견적과 복구 목표

위 항목은 모르는 상태에서 추정해 구현하지 않고 DEMO 어댑터와 안전 기본값으로 막아 둔다.
