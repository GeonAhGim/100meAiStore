# 자동 온라인 위탁판매 시스템 조사·실행 보고서

대상: 한국에서 스마트스토어를 우선 채널로 운영하려는 사업자  
기준일: 2026-09-04  
범위: 시장성, 법적·플랫폼 제약, 수익모델, 자동화 아키텍처, 90일 실행계획

## 결론

자동화 시스템은 만들 수 있지만, **일주일 순수익 500만 원은 소프트웨어만으로 보장할 수 없다.** 목표를 주간 공헌이익 500만 원으로 정의하고 SKU별 실현 마진, 주문량, 광고 효율, 취소·반품률로 검증해야 한다. 첫 단계의 성공 기준은 대량 상품 등록이 아니라 다음 네 가지다.

1. 모든 상품에 공급가·배송비·플랫폼 수수료·광고비·반품충당금을 반영한다.
2. 상품정보·이미지 사용권·인증/금지상품·원산지 등 필수 정보를 통과하지 못하면 등록을 차단한다.
3. 공급사 품절과 가격 인상을 빠르게 반영해 역마진과 배송지연을 막는다.
4. 자동 발주·가격 변경·광고 집행에는 금액 한도와 사람 승인을 둔다.

## 확인된 사실과 의미

네이버 커머스API는 스마트스토어 기능을 HTTP API로 제공하지만, API센터 가입, 애플리케이션 등록, 사용 권한 및 인증이 선행되어야 한다. 최신 문서에는 상품 등록/수정, 판매상태, 옵션 재고·가격, 주문 조회, 발주 확인과 발송 처리 범주가 있다. 따라서 브라우저 스크래핑보다 공식 API 어댑터가 운영 기반이어야 한다.

전자상거래 소비자보호법 체계상 통신판매업 신고, 표시, 청약철회 및 환급 의무가 존재한다. 특히 판매자가 재화를 직접 보유하지 않는 위탁판매라도 소비자와 계약한 판매자의 책임이 사라지는 것으로 보아서는 안 된다. 법령은 반환 또는 철회 사유에 따라 대금 환급 기한을 두고 있어 주문·클레임 상태와 증빙을 시스템에 보존해야 한다. 신고 면제 고시는 직전년도 거래 50회 미만 또는 간이과세자 등의 기준을 두지만, 주 500만 원 목표 운영은 면제를 전제로 설계하면 안 된다.

## 수익 역산

기본 가정은 플랫폼 수수료 6%, 광고비 10%, 반품충당금 5%다. 이는 시장 평균이 아니라 초기 보수적 설정값이며 실제 정산 데이터로 카테고리별 교체해야 한다.

| 판매가 | 공급가 | 배송비 | 주문당 공헌이익 | 주 500만 원 필요 주문 |
|---:|---:|---:|---:|---:|
| 30,000원 | 15,000원 | 3,000원 | 5,700원 | 878건 |
| 50,000원 | 25,000원 | 3,000원 | 11,500원 | 435건 |
| 100,000원 | 50,000원 | 3,000원 | 26,000원 | 193건 |

이 표에는 인건비, SaaS/API 비용, 고정 광고 제작비, 부가가치세와 소득세/법인세가 포함되지 않았다. 따라서 실제 순수익 목표라면 주간 공헌이익 목표를 500만 원보다 높게 잡아야 한다.

## 권장 아키텍처

- Control plane: 정책, 승인, 예산·가격 한도, 워커 상태, 감사 로그
- Queue: SQLite로 시작하고 처리량이 늘면 PostgreSQL 기반 큐로 이전
- Workers: catalog, compliance, listing, inventory, order, fulfillment, claim, settlement, profit, codex
- Adapters: 공급사와 판매채널마다 공식 API/CSV 어댑터를 별도 구현
- Safety: 멱등키, lease, 지수 백오프, dead-letter, 요청/응답 감사, dry-run, 비밀정보 환경변수 보관
- Human gates: 신규 SKU 첫 등록, 10% 초과 가격변경, 고액 자동발주, 규제 카테고리, 환불 예외

AI는 제목·설명 초안, 카테고리 후보, 문의 분류, 이상 탐지, 실험 분석에 사용한다. 가격·재고·주문 상태의 원장은 결정론적 코드와 공식 API가 맡아야 한다.

## 90일 실행계획

### 1~2주: 자격과 데이터

- 사업자/통신판매/정산 계정과 반품 주소 준비
- 공급사 1곳, 채널 1곳만 선정하고 API 또는 CSV 계약 확인
- 후보 100개 SKU에 공급가·배송·반품·수수료를 채워 20개 이하로 축소
- 금지/인증상품과 이미지 저작권 체크리스트 확정

### 3~4주: 폐쇄형 파일럿

- 상품·재고 조회 어댑터 연결, 등록은 승인 후 수행
- 하루 1~2회 재고/가격 동기화와 품절 자동중지
- 주문을 공급사 양식으로 변환하되 발주는 사람 승인
- 목표: 주문 누락 0, 역마진 0, 재고 불일치율 측정 가능

### 5~8주: 수익 검증

- SKU별 공헌이익·광고효율·취소/반품률 대시보드
- 7~14일 단위로 저성과 SKU 중지, 우수 SKU 상세페이지/가격 실험
- 50건 이상 안정 처리된 공급사만 제한적 자동발주 허용
- 목표: 세전 공헌이익 양수, 95% 이상 정시 발송, 클레임 원인 추적 가능

### 9~12주: 확장 판단

- 이익 SKU만 유사 카테고리 확장
- 공급사 장애·품절 대응과 채널별 rate limit 강화
- 실제 데이터로 주간 500만 원 도달에 필요한 트래픽·전환율·광고예산 산출
- 목표가 비현실적이면 SKU, 가격대, 채널 또는 기간을 조정

## 중단 기준

- 이미지/상표 사용권을 공급사가 서면으로 보장하지 않음
- 실현 공헌이익률이 4주 연속 정책 하한 미달
- 공급사 품절·송장 지연 때문에 판매자 지표가 반복 악화
- 자동화가 플랫폼 약관상 허용된 공식 API 없이 화면 조작/우회에 의존
- 환불·반품 비용이나 광고비를 포함하면 목표 이익이 소멸

## 조사 한계

판매 수수료는 채널, 카테고리, 결제수단, 프로그램 가입 상태에 따라 달라 하나의 공식 비율로 고정하지 않았다. 공급사 계약, 실제 전환율, 광고 데이터, 반품률이 없으므로 주 500만 원 달성 확률이나 시점을 산정할 수 없다. 이 문서는 법률·세무 자문이 아니며 실제 판매 전 전문가 확인이 필요하다.
