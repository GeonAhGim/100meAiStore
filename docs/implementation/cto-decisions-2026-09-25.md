# CTO/CA 결정 기록 — 2026-09-25

운영자가 사람 결정이 필요한 항목을 CTO/CA(Claude Code)에 위임했다("사람결정이 필요한 부분은
cto이자 ca인 니가 결정하고 pm에게 내려"). 아래는 그 위임에 따른 결정과 PM(마일스톤 워크플로)에
내린 작업이다.

## 위임의 경계

결정은 위임됐지만, 실물 조건은 결정으로 대신할 수 없다. 다음은 운영자만 마련할 수 있으므로
G1~G5는 계속 **DEMO**이고, 이 문서는 어떤 LIVE 권한도 만들지 않는다.

| 게이트 | 운영자만 마련할 수 있는 것 |
|---|---|
| G1 채널 | 네이버 커머스 API센터·쿠팡 WING 판매자 계정과 API 키(비밀 백엔드에만 보관) |
| G2 공급처 | 공급처 선정과 계약, 허가된 마스킹 샘플 |
| G3 법률 | 개인정보·보존 의무에 대한 날짜가 있는 법률 검토 책임자 |
| G4 쓰기 | 실제 금액·수량 한도에 대한 사업 판단 |
| G5 운영 | 유료 클라우드 지출 승인과 결제 수단 |

## 결정

### D1. M3.3 실제 연동 전 release review — DEMO 운영 승인, LIVE 불가

DEMO(로컬 PC, 합성 fixture) 운영은 승인한다. LIVE 전환은 G1~G5가 LIVE로 재승인되기 전까지
불가(no-go)다. 검토 기록은 저장소 증거에서 자동으로 만들어져야 하며, 운영·보안·복구 항목별
판정과 막고 있는 게이트를 열거한다. 판정은 fail-closed: 근거가 없으면 LIVE는 항상 no-go다.

PM 작업: M3.3을 로컬 풀이 구현한다(owner local-llm).

### D2. M4.8 실제 읽기 Discovery — 오프라인 준비분을 분리

실제 읽기는 G1·G2·G3 뒤에만 가능하다. 그 전에 할 수 있는 것을 **M4.8a**로 분리한다.
G1·G2·G3 승인 패킷(backlog의 "Approval packets" 항목)을 알려진 사실과 명시적 미확인 항목으로
채우고, 마스킹 샘플을 받으면 그대로 돌릴 수 있는 읽기 Discovery 하네스를 fixture로 검증한다.
M4.8 본체는 M4.8a와 실제 게이트 승인에 의존하며 운영자 몫으로 남는다.

### D3. M4.9 운영 배포·호스팅 — 방향과 초기 목표 확정, 유료 실행은 운영자

- 호스팅 방향: D-09대로 Google Cloud 서울, 요청 기반 scale-to-zero Cloud Run, 비밀은 Secret
  Manager/KMS. PostgreSQL 물리 호스트(Cloud SQL 대 저비용 서버리스 PostgreSQL)는 배포 직전
  견적 비교로 고른다(DEC-08). 월 비용 한도는 D-09의 목표 3,000원, 경고 24,000원, 상한 30,000원.
- 초기 RPO/RTO(DEC-02): 단일 운영자·저물량 MVP 기준 **RPO 24시간, RTO 4시간**. 물량이
  늘거나 영업시간 약속이 생기면 다시 정한다.
- 오프라인 준비분을 **M4.9a**로 분리한다. 로컬 SQLite 백업·복원 리허설 도구와, 복원이
  위 RPO/RTO를 만족함을 보이는 테스트, 그리고 이 결정을 담은 G5 패킷 초안(가격은 "배포 직전
  재확인" 표시). M4.9 본체(실제 유료 프로비저닝)는 운영자 몫으로 남는다.

## D4. M5 — DEMO를 운영할 수 있는 제품 기능 (03:20 추가)

M3.3·M4.8a·M4.9a가 통합돼 로컬 풀이 할 마일스톤이 바닥났다. 남은 M4.8·M4.9는 LIVE 실물 조건을
기다린다. 그동안 아키텍처 요약(00-summary-ko.md)이 약속했지만 코드에 없는 기능을 오프라인으로
만든다. 모두 주입된 시계와 로컬 DEMO 싱크로 테스트하며 외부 호출은 없다.

  `config.json`을 파일 이름만으로 자격증명으로 본 오탐이다(내용에 비밀값 없음). M5.1이 이를
  내용 기반 검사로 고치며, 완료 확인은 `python -m packages.store_core.release_review` 종료 코드 0.
